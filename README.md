# PwdVault

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](https://opensource.org/licenses/MIT)

Локальный, безопасный менеджер паролей для Windows и Android. Все данные хранятся только на вашем устройстве в зашифрованном виде. Никаких облаков, трекеров и телеметрии.

Установщики для Windows (`.exe`/`.msi`) и Android (`.apk`) доступны в разделе [Releases](../../releases).

## Возможности

- Генерация криптографически стойких паролей (настройка длины, наборов символов, исключение неоднозначных).
- Создание, удаление и поиск записей с мгновенным сохранением на диск.
- Ручная блокировка хранилища и полное удаление данных (сброс до заводских настроек).
- Автоматическая очистка буфера обмена через 30 секунд после копирования.
- Автоматическое создание резервных копий (`.bak`) при каждом сохранении.
- Автоблокировка при потере фокуса (при сворачивании приложения на Android).
- Адаптивный интерфейс: сайдбар на ПК и нижняя панель навигации на мобильных устройствах.
- Минималистичный интерфейс на базе иконок (Lucide), тёмная тема с фиолетовым акцентом.

## Безопасность

Приложение использует проверенные криптографические примитивы:
- **Деривация ключа**: Argon2id (параметры OWASP: 64 MB памяти, 3 итерации, 4 потока).
- **Шифрование**: AES-256-GCM (аутентифицированное шифрование).
- **Управление памятью**: Мастер-пароль и производные ключи никогда не сохраняются на диск. В оперативной памяти они зануляются (`zeroize`) сразу после использования.
- **Целостность**: Вектор инициализации (nonce) генерируется заново для каждой операции записи. Подмена байтов в зашифрованном файле приводит к ошибке расшифровки.

## Технологический стек

- **Frontend**: React 18, TypeScript, Vite.
- **Backend**: Rust, Tauri v2.
- **Криптография**: `argon2`, `aes-gcm`, `secrecy`, `zeroize`.
- **Буфер обмена**: `tauri-plugin-clipboard-manager` (кроссплатформенное решение).

## Локальная разработка

Для запуска исходников потребуются: Node.js (v18+), Rust (stable), а также системные зависимости Tauri (MSVC Build Tools на Windows, WebKit2GTK на Linux, Xcode CLI на macOS).

```bash
# Установка зависимостей фронтенда
npm install

# Запуск приложения в режиме разработки (Desktop)
npm run tauri dev
```

### Сборка релизов

**Для Windows:**
```bash
npm run tauri build
```
Готовые установщики появятся в `src-tauri/target/release/bundle/`.

**Для Android:**
Потребуется установленный Android Studio (SDK и NDK), а также JDK 17.
```bash
# Запуск на подключенном устройстве/эмуляторе
npx tauri android dev

# Сборка подписанного APK
npx tauri android build --apk
```
Готовый APK будет находиться в `src-tauri/gen/android/app/build/outputs/apk/universal/release/`.

## Расположение данных

Приложение сохраняет локальные файлы в системной директории данных:
- **Windows**: `%APPDATA%\com.pwdvault.app\`
- **Android**: Внутренняя песочница приложения (`/data/data/com.pwdvault.app/`)

Основные файлы:
- `vault.enc` — зашифрованное хранилище записей.
- `vault.enc.bak` — резервная копия предыдущего состояния.
- `settings.json` — настройки интерфейса (не содержит паролей).

## Модель угроз (Threat Model)

Данный раздел описывает границы ответственности приложения и честно фиксирует, от чего `sec-vault` защищает, а от чего — нет.

### 1. Защищаемые активы
*   **Мастер-пароль**: никогда не сохраняется на диск, используется только для деривации ключа.
*   **Производный ключ (256-bit)**: хранится только в оперативной памяти в защищенной обертке (`secrecy::SecretBox`).
*   **Расшифрованные секреты**: пароли от записей, находящиеся в памяти во время сессии.
*   **Файл хранилища (`vault.enc`) и его резервные копии (`.bak`)**: зашифрованный слепок данных на диске.

### 2. Допущения о среде
Модель угроз строится на следующих предположениях:
*   Операционная система пользователя не скомпрометирована (отсутствуют руткиты, кейлоггеры и вредоносное ПО с правами администратора/пользователя).
*   Пользователь скачал исполняемый файл из официального источника (раздел Releases репозитория).
*   Пользователь использует надежный мастер-пароль и хранит его в тайне.

### 3. В области защиты (In-Scope)
| Угроза | Защищено? | Как реализовано в коде |
| :--- | :--- | :--- |
| **Кража файла `vault.enc`** | **Да** | Данные зашифрованы AES-256-GCM. Ключ невозможно получить без мастер-пароля (защита от перебора через Argon2id: 64 MB RAM, 3 итерации). |
| **Подмена/повреждение файла** | **Да** | Аутентифицированное шифрование GCM. Любое изменение байтов (ciphertext, nonce, tag) приведет к ошибке расшифровки (покрыто тестами). |
| **Утечка данных через XSS/WebView** | **Да** | Криптография изолирована в Rust. Фронтенд не имеет доступа к мастер-паролю или ключу. Строгий CSP (без `unsafe-inline` и `eval`) блокирует внедрение скриптов. |
| **Логирование секретов** | **Да** | Пароли передаются через IPC с использованием `SecretString` (не реализует `Debug` и `Display`), что предотвращает их случайный вывод в консоль. |
| **Утечка через буфер обмена** | **Да** | Копирование происходит нативно через Rust (`arboard`). Буфер автоматически очищается через 10 секунд, если в нем всё еще находится скопированный пароль. |
| **Остаточные данные в RAM** | **Частично** | При блокировке сессии ключи уничтожаются (`zeroize`). Профиль сборки `panic = "abort"` предотвращает создание дампов памяти при критических ошибках. |

### 4. Вне области защиты (Out-of-Scope)
*   **Скомпрометированная ОС**: Если в системе есть кейлоггер, он украдет мастер-пароль при вводе. Если вредоносное ПО имеет доступ к памяти (ptrace), оно может прочитать ключи, пока хранилище разблокировано.
*   **Физический доступ**: Злоумышленник, имеющий доступ к разблокированному устройству, может увидеть пароли на экране или скопировать их.
*   **Слабый мастер-пароль**: Argon2id замедляет подбор, но не спасет от пароля вида `123456789012`.
*   **Атаки по сторонним каналам**: Время выполнения криптографических операций может теоретически зависеть от данных (хотя используемые библиотеки стремятся к константному времени).
*   **Безопасность цепочки поставок**: Мы полагаемся на crates.io, но не проводим аудит каждой транзитивной зависимости (рекомендуется периодически запускать `cargo audit`).

### 5. Остаточные риски
*   **Память фронтенда**: Введенный мастер-пароль и просматриваемые пароли кратковременно хранятся в состоянии React (JS). Злоумышленник с отладчиком (DevTools) может извлечь их оттуда.
*   **Своп/Гибернация ОС**: Страницы оперативной памяти (включая расшифрованные данные) могут быть записаны ОС в файл подкачки или гибернации на диск, где останутся после выключения.
*   **Бэкап `vault.enc.bak`**: При перезаписи файла создается резервная копия. Она остается на диске в зашифрованном виде, но злоумышленник, получивший доступ к диску, будет перебирать пароль к обоим файлам одновременно.

### 6. Стандарты и спецификации
*   [RFC 9106](https://datatracker.ietf.org/doc/html/rfc9106) — Рекомендации по использованию Argon2.
*   [NIST SP 800-38D](https://csrc.nist.gov/publications/detail/sp/800-38d/final) — Спецификация AES-GCM.
*   [OWASP Password Storage Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html) — Рекомендации по параметрам KDF.

## Важное примечание

Мастер-пароль не хранится нигде. В случае его утраты восстановить доступ к данным невозможно (даже при наличии файла `vault.enc` или его резервной копии). Придумывайте надежный пароль и храните его в безопасном месте.

# Secret Vault (sec-vault)

[![License: Apache 2.0](https://img.shields.io/badge/License-Apache%202.0-blue.svg)](https://opensource.org/licenses/Apache-2.0)

Локальный, безопасный менеджер паролей для Windows. Все данные хранятся только на устройстве пользователя в зашифрованном виде. Никаких облаков, трекеров и телеметрии. Архитектура спроектирована с параноидальным подходом к безопасности.

Установщик для Windows доступен в разделе [Releases](../../releases).

## Возможности

- Генерация криптографически стойких паролей (настройка длины, наборов символов, исключение неоднозначных).
- Создание, удаление и поиск записей с мгновенным сохранением на диск. Поддержка текстовых заметок.
- Ручная блокировка хранилища и полное удаление данных (сброс до заводских настроек).
- Автоматическая очистка буфера обмена через 10 секунд после копирования.
- Автоматическое создание резервных копий (`.bak`) при каждом сохранении.
- Минималистичный интерфейс на базе иконок (Lucide), ониксовая тема со светло-зеленым акцентом. Никаких инлайн-стилей.

## Безопасность

Приложение использует проверенные криптографические примитивы и практики:
- **Деривация ключа**: Argon2id (параметры OWASP: 64 MB памяти, 3 итерации, 4 потока).
- **Шифрование**: AES-256-GCM с использованием Associated Data (AAD). Заголовок файла (параметры KDF и соль) криптографически связан с шифротекстом. Изменение заголовка приводит к ошибке аутентификации.
- **Управление памятью**: Все секреты в Rust (мастер-пароль и пароли записей) оборачиваются в `SecretString`. При уничтожении сессии или записи память принудительно зануляется (`zeroize`).
- **Целостность**: Вектор инициализации (nonce) генерируется заново для каждой операции записи.
- **Изоляция WebView**: Строгий CSP (`script-src 'self'`, `style-src 'self'`). Инструменты разработчика (DevTools) отключены в релизной сборке.
- **Минимальные привилегии**: В `capabilities` оставлен только необходимый минимум разрешений для работы окна и событий.
- **Буфер обмена**: Изолирован от WebView. Работа происходит нативно через Rust (`arboard`).
- **Тестирование и CI**: 29 автотестов (включая проверки на подмену AAD, эталонные векторы NIST). Внедрен GitHub Actions (Clippy, тесты, `cargo audit`).

## Технологический стек

- **Frontend**: React 18, TypeScript, Vite.
- **Backend**: Rust, Tauri v2.
- **Криптография и системные вызовы**: `argon2`, `aes-gcm`, `secrecy`, `zeroize`, `arboard`.

## Локальная разработка

Для запуска исходников потребуются: Node.js (v18+), Rust (stable), а также системные зависимости Tauri (MSVC Build Tools на Windows).

```bash
# Установка зависимостей фронтенда
npm install

# Запуск приложения в режиме разработки
npm run tauri dev
```

### Сборка релиза

```bash
npm run tauri build
```
Готовые установщики (`.msi` и `.exe`) появятся в `src-tauri/target/release/bundle/`.

## Расположение данных

Приложение сохраняет локальные файлы в системной директории данных. В Windows это папка `%APPDATA%\com.secvault.app\`. 

Основные файлы:
- `vault.enc` — зашифрованное хранилище записей.
- `vault.enc.bak` — резервная копия предыдущего состояния.
- `settings.json` — настройки интерфейса (не содержит паролей).

## Модель угроз (Threat Model)

Данный раздел описывает границы ответственности приложения и честно фиксирует, от чего `sec-vault` защищает, а от чего — нет.

### 1. Защищаемые активы
*   **Мастер-пароль**: никогда не сохраняется на диск, используется только для деривации ключа.
*   **Производный ключ (256-bit)**: хранится только в оперативной памяти в защищенной обертке (`secrecy::SecretBox`).
*   **Расшифрованные секреты**: пароли от записей, находящиеся в памяти во время сессии.
*   **Файл хранилища (`vault.enc`) и его резервные копии (`.bak`)**: зашифрованный слепок данных на диске.

### 2. Допущения о среде
*   Операционная система пользователя не скомпрометирована (отсутствуют руткиты, кейлоггеры и вредоносное ПО с правами администратора).
*   Пользователь скачал исполняемый файл из официального источника (раздел Releases репозитория).
*   Пользователь использует надежный мастер-пароль и хранит его в тайне.

### 3. В области защиты (In-Scope)
| Угроза | Защищено? | Как реализовано в коде |
| :--- | :--- | :--- |
| **Кража файла `vault.enc`** | **Да** | Данные зашифрованы AES-256-GCM. Ключ невозможно получить без мастер-пароля (защита от перебора через Argon2id). |
| **Подмена KDF-параметров** | **Да** | Метаданные заголовка передаются в GCM как Associated Data (AAD). Изменение заголовка ломает тег аутентификации. |
| **Подмена ciphertext** | **Да** | Аутентифицированное шифрование GCM. Любое изменение байтов приведет к ошибке расшифровки. |
| **Утечка данных через XSS/WebView** | **Да** | Криптография изолирована в Rust. Строгий CSP (без `unsafe-inline` и `eval`) блокирует внедрение скриптов. |
| **Логирование секретов** | **Да** | Пароли в IPC-вызовах и структурах хранилища обернуты в `SecretString` (не реализует `Debug` и `Display`). |
| **Утечка через буфер обмена** | **Да** | Копирование происходит нативно через Rust (`arboard`). Буфер автоматически очищается через 10 секунд. |
| **Остаточные данные в RAM** | **Частично** | При блокировке сессии ключи и пароли записей уничтожаются (`zeroize`). Профиль сборки `panic = "abort"` предотвращает создание дампов памяти. |

### 4. Вне области защиты (Out-of-Scope)
*   **Скомпрометированная ОС**: Кейлоггеры украдут мастер-пароль при вводе. Вредоносное ПО с доступом к памяти (ptrace) может прочитать ключи, пока хранилище разблокировано.
*   **Физический доступ**: Злоумышленник, имеющий доступ к разблокированному устройству, может увидеть пароли на экране.
*   **Слабый мастер-пароль**: Argon2id замедляет подбор, но не спасет от пароля вида `123456789012`.
*   **Атаки по сторонним каналам**: Время выполнения криптографических операций может теоретически зависеть от данных.
*   **Цепочка поставок**: Приложение полагается на crates.io. Регулярный аудит проводится через `cargo audit` в CI, однако полный ручной аудит каждой транзитивной зависимости не выполняется.

### 5. Остаточные риски
*   **Память фронтенда**: Введенный мастер-пароль и просматриваемые пароли кратковременно хранятся в состоянии React (JS).
*   **Своп/Гибернация ОС**: Страницы оперативной памяти (включая расшифрованные данные) могут быть записаны ОС в файл подкачки или гибернации на диск.
*   **Бэкап `vault.enc.bak`**: При перезаписи файла создается резервная копия. Она остается на диске в зашифрованном виде, но злоумышленник будет перебирать пароль к обоим файлам одновременно.

### 6. Стандарты и спецификации
*   [RFC 9106](https://datatracker.ietf.org/doc/html/rfc9106) — Рекомендации по использованию Argon2.
*   [NIST SP 800-38D](https://csrc.nist.gov/publications/detail/sp/800-38d/final) — Спецификация AES-GCM.
*   [OWASP Password Storage Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html) — Рекомендации по параметрам KDF.

## Важное примечание

Мастер-пароль не хранится нигде. В случае его утраты восстановить доступ к данным невозможно (даже при наличии файла `vault.enc` или его резервной копии). Придумывайте надежный пароль и храните его в безопасном месте.
